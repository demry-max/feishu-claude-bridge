# 上线单：事件订阅、长连接、补拉与演练

给部署和发布的人看。这里只写通用内容；本机的应用、服务标签、会话 id 不写进仓库。

## 首次升级到带补拉的版本：先看这条

去重表 `data/inbound-seen.json` 从这个版本才开始记，第一次启动时是空的。首轮补拉会把重启前约 `BRIDGE_STALE_MS`（默认 10 分钟）内、旧版本**已经答过**的消息（owner 私聊、`ALLOW_CHATS` 群里 @ 机器人的）再交给处理链：里面如果是让机器人做事的指令，会做第二遍。任选一种避开：

- 挑最近 10 分钟（或你设的过期时长）没有人给机器人发过消息的时刻重启；
- 或先在 `.env` 加 `BRIDGE_BACKFILL=off` 重启，过了过期时长以后删掉这一行再重启一次。

去重文件被删或损坏（启动日志 `[dedupe] … 按空表起步`）时同样适用。

## 1. 代码注册的事件

`src/index.js` 的事件注册段（`const eventDispatcher`）注册了 5 种：

| 事件 | 用途 | 缺了会怎样 |
|---|---|---|
| `im.message.receive_v1` | 收消息（私聊、群里 @ 机器人） | 实时收不到任何消息（补拉只能零星捡回一部分，不能代替它） |
| `im.message.reaction.created_v1` | owner 对心跳消息点的表情记成信号 | 心跳不知道你点过表情，其余不变 |
| `im.message.message_read_v1` | owner 读了心跳消息记成信号；未读暂停靠它 | 开了 `HEARTBEAT_UNREAD_PAUSE` 时消息一直算未读，心跳会因此暂停发送 |
| `im.message.recalled_v1` | 撤回事件（只计数） | 少一项计数 |
| `card.action.trigger` | 卡片按钮回调：心跳消息按钮、定时任务确认卡（`SCHED_APPROVAL_MODE=button`） | 按钮点了不生效 |

- 开发者后台「事件与回调 → 事件配置」选「使用长连接接收事件」，添加前 4 种事件。
- **卡片回调要在「回调配置」里单独选长连接**（事件配置里的选择管不到它），再订阅 `card.action.trigger`。
- 改完都要创建版本并发布。

## 2. 同一应用只起一个长连接事件消费方

飞书长连接是集群投递、不广播：同一应用同时连着几个客户端时，每条事件只到其中随机一个（见飞书 Node SDK 的 README）。

- AGENTS §3C 让 lark-cli 和桥接共用同一个应用，所以**不要**对这个应用跑 `lark-cli event consume`，也不要用别的程序订阅它的事件。
- 前台实例和常驻服务不要同时用同一个应用运行：事件会被分走，还可能回两遍。

## 3. 补拉与补漏的调用量

长连接启动就绪、重连成功后各补拉一次；另按 `BRIDGE_SWEEP_MIN` 定时补漏。每轮对每个已知会话调「获取会话历史消息」接口。

```
每天调用量 ≈ 已知会话数 × (86400 / (BRIDGE_SWEEP_MIN × 60) + 每天重连次数) × 页数
```

- 已知会话：owner 私聊、`ALLOW_CHATS` 里的群、7 天内给机器人发过消息的会话（最多记 50 个）。
- 页数：通常 1；每个会话每轮最多 3 页（每页 50 条）。
- 例：5 个会话、默认 10 分钟、不算重连、每次 1 页 ≈ 720 次/天。
- `BRIDGE_SWEEP_MIN=0` 只关定时补漏（启动与重连后仍补拉）；`BRIDGE_BACKFILL=off` 全部关掉。

## 4. 补拉需要的权限（未核实）

接口是 `im.v1.message.list`，需要读历史消息的权限。**具体 scope 名、私聊和群是否分开，未核实**，发布时在开发者后台按接口文档核对后开通，再发布版本。待核对的候选：`im:message:readonly`、`im:message.group_msg`（「获取群组中所有消息」）。

同时核对：列表接口返回的 `mentions[].id` 是不是 open_id（群里是否 @ 了机器人靠它判断；不是的话群消息会全部被跳过）。

缺权限时的表现：日志一行 `[backfill] 拉取失败（p2p|group）code=<飞书错误码>`（缺权限常见 `99991672`），同一会话每小时最多一行；**实时收消息不受影响**。

## 5. 断网 / 假死演练（发布时做）

先停掉常驻服务、起一个前台实例（自己起、自己记 PID，见第 2 节）；要在常驻服务上做，先经负责人同意。

1. **断网 1 分钟再恢复**
   - 日志出现 `[ws] 重连中`、`[ws] 已重连` 和 `[backfill]` 记录。
   - 断网期间私聊发的一条会被回答；超过 `BRIDGE_STALE_MS` 才拉到的只登记不回答（日志 `[stale]`）。依赖第 4 节的权限；没开通时只能靠飞书重推。
2. **假死超过 60 秒**：`kill -STOP <自己记下的 PID>`，过 60 秒以上再 `kill -CONT <同一个 PID>`。
   - 结果应是重连（随后补拉），或看门狗 / 巡检让进程退出（日志 `[exit] …`），常驻服务由进程管理器拉起。
3. **重启不重答**：同一条消息在重启前后只答一次。
